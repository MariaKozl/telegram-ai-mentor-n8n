# Кейс: ИИ-ментор для персонального обучения

## Контекст и цель

Учебный проект для взаимодействия с ИИ-помощником через Telegram, оформленный для портфолио. Цель — связать диалог об учебных интересах с поиском материалов и формированием понятного ответа.

## Роль автора

Мария Козлянинова — автор сценария и workflow. Работа включала проектирование последовательности действий, настройку интеграций и инструкций LLM, маршрутизацию сообщений и подготовку данных для генерации ответа.

## Требования, отражённые в конфигурации

1. Получать текст сообщения из Telegram.
2. Уточнять учебную цель и уровень знаний пользователя.
3. Предлагать план из пяти тем с ключевыми понятиями.
4. Запрашивать подтверждение плана перед переходом к материалам.
5. Сохранять контекст диалога отдельно для каждого chat ID.
6. При поисковой команде выполнять HTTP-запрос к Tavily.
7. Передавать найденные материалы в отдельную LLM-ноду и возвращать ответ в Telegram.

Требования к диалогу задаются промптом. Их фактическое выполнение необходимо проверять на тестовых диалогах.

## Интеграционное решение

Первый агент обрабатывает запрос пользователя и либо отвечает напрямую, либо формирует строку `tavily(query="...")`. JavaScript-нода проверяет формат, после чего IF выбирает ветку процесса.

В поисковой ветке из строки извлекается запрос. HTTP Request отправляет его в Tavily Search API методом POST. Тело запроса содержит `query`, `search_depth: "basic"` и `include_answer: true`.

Для второго агента формируется контекст из массива `results`: заголовков, URL, содержимого источников и оценок релевантности. Оценка релевантности описывает соответствие запросу и не является вероятностью достоверности. Поле `answer`, запрошенное у Tavily, текущая логика отдельно не использует.

Вторая LLM получает инструкцию отвечать на русском языке и использовать предоставленные материалы. Затем workflow отправляет ответ в Telegram.

## Результат и границы подтверждения

Подготовлен workflow из 14 нод, объединяющий канал общения, LLM, память диалога и внешний поиск. Экспорт подтверждает конфигурацию и связи нод. Метрики качества, экономии времени и успешности запросов не измерялись; эта публикационная версия не запускалась при подготовке репозитория.

## Аналитические выводы

Промпт управляет поведением модели, но не заменяет явное хранение состояния. Для гарантированного прохождения тем без повторов следует хранить план, текущий шаг и изученные темы отдельно.

Текстовая команда упрощает прототип, но чувствительна к формату ответа. Следующая версия может использовать структурированный результат с полями `action` и `query` и проверкой схемы.

Перед промышленным применением нужны обработка отказов API, защита данных пользователей, проверка устойчивости к инструкциям из внешних источников и контроль качества ответа.
